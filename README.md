# Build Your Dream House — exterior playable

**▶ Play it: https://andersonigarashi.github.io/HouseCleanerPlayable/**

Playable ad: clean a wrecked yard with a broom, watch the house get rebuilt, then paint the walls and roof with a roller. Exterior version (the interior steps FLOOR / FURNITURE show locked as a teaser).

three.js renders the 3D scene, pixi.js renders the 2D UI/FX on a transparent canvas on top, Howler plays audio and `@smoud/playable-sdk` handles the ad-network lifecycle.

## Run

```bash
npm install
npm run dev      # http://localhost:3000 (the LAN address is printed too, for phones)
npm run build    # single inlined HTML in dist/
npm run typecheck
```

Every push to `main` runs `.github/workflows/pages.yml`, which builds the playable and publishes it to GitHub Pages together with the showcase page in `pages/index.html` (phone frame on desktop, full screen on phones). The raw playable is served as `play.html`.

## Code

| Path | What |
|---|---|
| `src/Game.ts` | Flow / state machine: intro → CLEAN → rebuild cinematic → PAINT (walls, roof) → COMPLETE → end card, tutorial hints, idle bailout, store redirect |
| `src/config.ts` | Tunables: steps, paint palettes, sweep radius, auto-finish thresholds, camera, haptics, store rules |
| `src/world/World3D.ts` | three.js scene: GLB loading (meshopt), one shared atlas material, responsive camera framing, debris sweeping, clipping-plane paint wipe, flowers, camera swing |
| `src/ui/*` | pixi UI: top bar (level + progress), step bar, color palette, broom/roller tools, tutorial hand, particles (dust, sparkles, confetti, paint), end card |
| `src/core/*` | tween engine (squash & stretch helpers), sound, asset imports |

Painting works by keeping the painted and unpainted houses on top of each other and clipping them against a moving plane pair along the camera's right axis, so each pixel shows exactly one of them.

## Assets

Everything is generated by the scripts in `../Files/Scripts` and copied into `assets/`:

1. `make_atlas.py` — 128-color palette → `Textures/atlas.png` (256×128) + `palette.json`
2. `build_house.py`, `build_broken.py`, `build_props.py`, `export_all.py` (run inside Blender via the Blender MCP / bpy) — every model is flat-colored through the atlas UVs and exported one `.glb` per asset to `Files/GLB` (meshopt compressed)
3. `build_icons.py` (Blender) → `2D/renders`, then `make_2d.py` (Pillow) → outlined icons, UI panels, buttons, logo, VFX sprites in `2D/final` (WebP copies used by the game in `2D/webp`)
4. `make_audio.py` (numpy synthesis) → `Audio/wav`, then `encoder/encode.js` (lamejs) → `Audio/mp3`

The Blender scene with every asset laid out is `Files/Blender/HouseCleaner.blend`. It holds manual fixes made after generation, so it is now the source of truth: to pick up edits made there, re-export without rebuilding (writes `Files/GLB` and copies into `assets/models`):

```bash
"C:\Program Files\Blender Foundation\Blender 5.2\blender.exe" --background ../Files/Blender/HouseCleaner.blend --python ../Files/Scripts/export_from_blend.py
```

Re-running the `build_*.py` / `export_all.py` generators would regenerate the meshes and drop those manual edits.
